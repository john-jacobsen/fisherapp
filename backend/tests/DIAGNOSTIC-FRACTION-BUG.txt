TASK 2: CURL SIMULATION RESULTS

IMPORTANT — TEST ARTIFACT DISCOVERED:
  curl -d '{"answer":"\\frac{5}{8}"}' sends JSON with \\frac (two bytes: \\ + f).
  JSON parser sees \\ → single backslash, so backend gets \frac{5}{8}. CORRECT.

  BUT: curl -d '{"answer":"\frac{5}{8}"}' sends JSON with \f — which is the
  JSON form-feed escape sequence (U+000C). The backend receives chr(0x0C) + "rac{5}{8}",
  NOT a backslash. This is INVALID JSON but FastAPI / Python's json module parses
  \f as form feed per the JSON spec (RFC 8259 §7).

  Several initial curl test attempts used this incorrect encoding and produced
  misleading "is_correct: false" results. These were TEST ARTIFACTS, not real bugs.

CORRECT SIMULATION (using Python urllib inside Docker, proper json.dumps encoding):
